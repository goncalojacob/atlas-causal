## A1. The front card sometimes greets a funder with slugs and "0 steps"

**Severity: blocks the demo.** It is intermittent: the reviewer saw it on 3 of
8 loads.

**Seen.** `first-1280.png` (15 s budget), `first-1280-b40.png` (40 s) and
`first-390.png` (phone, 15 s). The intro card reads *"Start here:
how-the-colonial-war-ended-the-regime  Atlas causal · 0 steps"*, *"Accounts
to read: how-the-colonial-war-ended-the-regime, who-was-buying"*, and under
"What most of it hangs on": *world-war-ii, world-war-i,
carnation-revolution-1974, kosovo-war, eec-accession-1986,
operation-odyssey-dawn*. Behind the card the map already shows "World War I",
"25 April" and "Charter of the United Nations". The titles had arrived, and
the card did not redraw. `first-1280-b5.png` (5 s) and two `--dump-dom` runs
at 5 s and 40 s show the same card with proper titles and "12 steps". The
graph has the same fault. In `lens-japan-graph.png`
(`?focus=actor:japan&view=graph`, 8 s) every node has its name and the chip
still reads **"ACTOR loading…"**.

**Why.** `src/intro.js` draws the card when it is created, before any
attribute shard has arrived. Titles and narrative steps are attributes since
I3. Only `redrawForShards` in `src/main.js` (about line 389) redraws the
card, once per animation frame after a shard arrives. Several things can
spoil that one frame: a redraw before `intro.refresh()` in the same function
throws, the tab is hidden when the frame is due, or a shard arrives while a
redraw is already booked. In each case the card keeps the ids it started
with. The lens chip works the same way. The reviewer could not run a real
browser with a real clock here. The previous reviewers' `docs/screens/m86-*.png`
show titles, so this is a race and the usual state is correct. But a funder
who gets the slug version keeps it for as long as the card is open.

**Fix (lane A).** Two changes. First, nothing on the page prints an id where
a title belongs. While the title is missing, print the "loading…" the chips
already use (`LOADING_LABEL` in `src/attributes.js`) and never `e.id`.
Second, the intro, the chips and the composer stop redrawing from the
landing callback. They redraw from the atlas's own attribute count (the
`arrived` counter the render keys read). Each subscribes once, compares the count to the one it last
drew, redraws when the count has moved, and checks again on
`visibilitychange`. A browser test at rest after `settledShards`: no
`.intro-go` and no `.lens-name` text equals its `data-id` or the loading
label.
