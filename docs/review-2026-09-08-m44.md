## Findings, most serious first

**1. Set 1 cannot import: 29 of Appendix A's 36 are already in the cursor's
`done`.** `tools/import/wikidata.mjs:748` filters `wanted.filter(id =>
!done.has(id))`, and `runs.import.done` holds 29 of the 36 Q-ids — exactly
deviation 447's list, which says "they sit in the import cursor's `done`".
Ticking them is a no-op. Set 1, the whole argument of the round, lands **seven**
new items (Q153122, Q1048750, Q190315, Q426722, Q1429076, Q190758, Q15353665).
The brief mentions the rewind once, in §3d, conditional on an "option 2" that
does not exist in §8. **Owner.**

**2. Question 3's lane fix cannot be read by `--import`, and the schema refuses
the key.** Rewound, the 29 are refused again at `wikidata.mjs:995`.
`runImportMode` (line 861) walks `seeds.items` and never touches
`seeds.queries` — queries run only in `runCandidatesMode` — so a region per
query is unreachable; there is no item-to-query association anywhere. And
`schema/v1/import-seeds.json` has `"additionalProperties": false` on the root
*and* each query, with `items` pinned to `^Q[1-9][0-9]*$`, so the key is a
schema error and `tests/import-seeds.test.mjs` goes red. The fix needs a new
per-item table, a schema change, a tool change and a test: a code milestone,
not a data edit inside an import round. **Owner.**

**3. Adding the ticks to `items` makes 29 duplicates.** §3b says `items` must
hold "592 + the ticks"; deviation 447 says the 29 are "still in the seeds file's
`items`" — confirmed. `tests/import-seeds.test.mjs:49` fails on duplicates.

**4. `consensus` on `wikidata` alone passes rule 22, and one `wikidata`
citation defeats rule 22 entirely.** `src/validate/rules.js:1333-1348` tests
`cited.every(id => WIKIPEDIA_SOURCES.includes(id))` with `WIKIPEDIA_SOURCES =
['wikipedia-en','wikipedia-pt']` (~line 70). `wikidata` is a source record and
is what every imported record cites, so `consensus` on

validates clean. §4d asserts rule 22 covers this. It does not. This is the one
place the brief lets a run mark an argument `consensus` on a database row
