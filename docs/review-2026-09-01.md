# Architecture review — 1 September 2026

Adversarial review of `ARCHITECTURE.md` (revision 2) by a subagent, verbatim.
The assistant's verdicts and the owner's decisions are recorded in
`STATUS.md` and folded into `ARCHITECTURE.md`; this file is the raw input.

## 1. The index workflow is internally inconsistent, and the version that survives deploys a stale site

**Problem.** `validate.yml` fails PRs whose `data/index/` is stale, while `index.yml` regenerates the index after merge; both cannot be true, and the post-merge commit made with `GITHUB_TOKEN` never triggers `pages.yml`.

**When it bites.** A contributor's PR (or the Action's PR) adds one event and does not touch `data/index/`. The freshness check fails; the PR cannot merge. If instead PRs must carry the regenerated index, every PR rewrites `events.json` and `manifest.json` (counts), so the second of any two open PRs conflicts on merge, every time. If you drop the PR-side check and rely on `index.yml`: a merge to `main` fires `pages.yml` and `index.yml` in parallel; Pages deploys the old index; `index.yml` commits the new one with `GITHUB_TOKEN`, and GitHub does not run workflows for pushes made with `GITHUB_TOKEN` (documented behaviour, by design, to prevent loops). The site is one merge behind forever, and nobody notices because the next merge redeploys the previous state. If you later switch that commit to a PAT to fix it, you get the loop the rule was preventing.

**Severity.** blocks M0.

**Fix.** Pick one owner of the index: `main`, post-merge. PRs never touch `data/index/`; `validate.yml` on PRs checks records only. One workflow on push to `main`: checkout, `build-index`, commit if changed with `GITHUB_TOKEN`, then `upload-pages-artifact` and deploy *from the same checkout, in the same job*. The freshness invariant becomes an assertion on `main`, not on PRs. Branch protection must let the Actions bot push to `main` (ruleset bypass). Use `concurrency: { group: deploy, cancel-in-progress: false }`. The committed index still exists, so `python3 -m http.server` still runs; the owner runs `node tools/build-index.mjs` locally after adding records, which the sketch's own amendment already permits.

## 2. Pull requests opened by the Action get no CI

**Problem.** A PR created with `GITHUB_TOKEN` does not trigger `pull_request` workflows, so `validate.yml` never runs on contribution PRs.

**When it bites.** M2 acceptance ("it arrives as a validated PR") passes only because `contribution.yml` ran the validator itself; the PR has no status check. If you make `validate.yml` a required check, contribution PRs can never merge; if you do not, the reviewer sees a PR with no signal and the validation result is buried in the Action's log. Any later edit the reviewer pushes to the branch *does* trigger CI, so you get inconsistent behaviour on the same PR.

**Severity.** blocks M0 (it decides the token strategy the workflows are written against).

**Fix.** Create the branch and PR with a fine-grained PAT or GitHub App token scoped to contents + pull-requests on this repo, stored as a secret; do not reuse that token for the index commit in finding 1. Alternatively publish the validator result as a check-run via the API from `contribution.yml`. The PAT is the least setup; put its expiry in `CONTRIBUTING.md` so it is renewed.

## 3. Sharding by year window makes the graph queries wrong

**Problem.** `data.js` "loads whatever shards overlap the visible window", but consequences, ancestors and convergence need the whole graph, not the window.

**When it bites.** Year 1580 is visible; the user asks for convergence on Alcácer Quibir. Ancestors in 1415–1500 live in a shard that was not loaded; convergence returns a subset and presents it as the complete list of other branches. That is precisely the determinism the query exists to prevent, now caused by the loader. It appears the day the second shard exists and is invisible in tests, which run on one shard.

**Severity.** blocks M0 (it is the shape of `manifest.json` and the contract of `data.js`).

**Fix.** Split the index by *content*, not by period. A topology index that is always loaded whole: per event `{id, title, when, where, region}`, per edge `{id, from, to, type, confidence}`; roughly 100–150 bytes per record, so 5,000 events + 15,000 edges is ~2.5 MB raw, ~400–600 KB gzipped, still one request. Text (`summary`, `explanation`, `dispute`, `sources`) is loaded on demand. For that, break principle 1: the site *may* read `data/events/<id>.json` directly, because those files are already static assets on Pages and the id is the path. That removes the need for shards and `shards/` from the manifest entirely for the foreseeable decade. Sharding, if ever, is by topology bucket with the whole graph still present.

## 4. `region` stored on each event is the migration you promised not to need

**Problem.** A single hand-assigned `region` string per record means every change to the lane taxonomy is a rewrite of every record.

**When it bites.** World coverage arrives; Europe is split into lanes (Iberia, Mediterranean, Northern Europe) via `parent`. The 3,000 events tagged `europe` all sit on the parent lane; to move them you edit 3,000 files authored by other people, in one PR, conflicting with every open contribution. Also, "later a presence can be referenced instead of coordinates" turns `where` into a union type on the hottest field in the schema.

**Severity.** blocks M0.

**Fix.** Derive `region` in `build-index.mjs` by point-in-polygon of `where` against region polygons in `data/geo/regions.json` (continent unions of Natural Earth country polygons, generated once in `tools/`, public domain). Keep `region` on the record as an *optional* override for the honest cases (Tordesillas is about the Americas, signed in Castile). Lanes then change by editing one polygon file. Keep `where` always as coordinates; add an optional `within: <presence-id>` later, which is additive.

## 5. Records are immutable and undeletable, but nothing says what happens to a wrong one

**Problem.** There is no `status` field, so duplicates, retractions and merged events have no representation, and edge-id uniqueness stops meaning "one argument once".

**When it bites.** Two contributors file `capture-of-malacca-1511` and `conquest-of-melaka-1511` in the same month (transliteration makes duplicate slugs a certainty, and the uniqueness invariant cannot see them). You discover this after edges hang off both. With immutable ids and no tombstone you either delete a file (breaking every `aliases`, narrative step and shared URL pointing at it) or keep two events and two copies of `x--y--caused`. Same for an edge whose type is corrected: the id changes, the old file has to go somewhere.

**Severity.** blocks M0.

**Fix.** Add `status: active | merged | retracted` and `supersededBy: <id>` to the envelope. Validator: a `merged`/`retracted` record must have no active edges; `supersededBy` must resolve; aliases must be unique across ids *and* other aliases (invariant 2 currently says nothing about aliases). The index resolves superseded ids like aliases. Separately, define `aliases` as former ids only; alternative names for search go in a distinct field later. The form must search titles and aliases before allowing a new event.

## 6. One issue per record cannot express a contribution

**Problem.** The natural contribution is "one new event plus the two or three edges that connect it, plus a source not yet in the bibliography"; the sketch makes that three or four issues whose PRs fail validation until the others merge.

**When it bites.** A contributor files an event issue and two edge issues. Two PRs fail on "`from` does not resolve", the Action comments an error, the contributor believes they did something wrong. After the event PR merges, nothing re-runs the two failed ones. A new `source` filed separately is an orphan record that passes validation and is never cited.

**Severity.** fix before contributions open.

**Fix.** One issue = one bundle: `{ records: [ ...events, ...edges, ...sources ] }`, validated as a unit with references allowed to resolve inside the bundle, written to one branch, one PR. Add a validator warning for events with degree zero and for sources with no citers.

## 7. Prefilled issue URLs break for exactly the contributions worth having, and principle 5 is false as stated

**Problem.** The issue form's markdown body is not the storage format (the Action re-parses `### Field\n\nvalue` blocks into JSON), and the prefill URL has a length cap that a real explanation exceeds.

**When it bites.** GitHub rejects request URLs above roughly 8 KB (I believe 8,192 bytes, HTTP 414; unverified). An edge with a 1,500-word explanation, a dispute paragraph and two source refs is 5–7 KB before percent-encoding; UTF-8 accents encode to three bytes each, spaces to three. The prefill silently truncates or 414s. The form works for one-line events, fails for the argument the project exists for. Meanwhile `issue-to-files.mjs` is a parser of a markdown rendering of a form field layout, and drifts whenever a template field is renamed.

**Severity.** fix before contributions open.

**Fix.** The form produces the bundle JSON; `submit.js` copies it to the clipboard and opens one issue template with a single required textarea, `record`, plus a required licence checkbox. The Action extracts the fenced JSON and validates it. That makes principle 5 true and turns `issue-to-files.mjs` into thirty lines. Prefill the URL only when the encoded body is under ~6 KB; otherwise show the paste instruction. Delete the per-kind `event.yml` / `edge.yml` / `source.yml` templates; keep `correction.yml` (also a full replacement record with the same id).

## 8. A crafted issue body can write anywhere in the branch

**Problem.** The Action turns untrusted text into file paths and commits with a write token.

**When it bites.** `id: "../../.github/workflows/pages.yml"` becomes the file name; the resulting PR contains a workflow change from a stranger, which `CODEOWNERS` on `data/` does not cover. If any step interpolates `${{ github.event.issue.body }}` into `run:`, that is shell injection with a token that can push. A source with `"url": "javascript:..."` passes the schema, is rendered as a link in `panel.js`, and `esc()` does not help. The issue template auto-applies the `contribution` label, so any account triggers the Action, which creates branches and PRs at whatever rate spam arrives.

**Severity.** fix before contributions open.

**Fix.** Validate ids against `^[a-z0-9]+(-[a-z0-9]+)*$` before any filesystem call, and write only to `data/<kind>/<id>.json` with `path.basename`. Pass the body to scripts via `env`, never `run:` interpolation. Validator rule: `url` must be `http(s)`. Trigger the Action on a label only a maintainer can apply (`accepted`), not the auto-applied one. Delete branches on PR close.

## 9. Attribution and consent are self-asserted strings, which CC BY-SA cannot live with

**Problem.** `author` is free text set by the contributor, is a single value, and there is no record of consent to the licence.

**When it bites.** Someone submits under "Gonçalo Jacob" or under a living historian's name. A stranger corrects your record; the file still says one author, but BY-SA requires attributing both, and `revised` is whatever the form put there. Someone asks for their contributions to be removed; you cannot find them because `author` was a display name they typed differently three times.

**Severity.** fix before contributions open, but the field shape is M0.

**Fix.** `authors: [ { name, github } ]` from day one; the Action sets `github` from the issue opener and appends on corrections; `created`/`revised` are set by the Action or derived from git at index time (a date from git is not attribution, principle 4 is intact). Required checkbox in the issue template stating the CC BY-SA 4.0 grant and that the text is the contributor's own; GitHub's Terms (section D.6, inbound = outbound) back it up but the explicit checkbox is what you show later.

## 10. One root `LICENSE` claims CC BY-SA over code and over data you cannot relicense

**Problem.** CC BY-SA 4.0 is unsuitable for `src/` and incompatible with the ODbL geometry the sketch plans to import.

**When it bites.** M3, when someone forks the code: CC BY-SA on JavaScript is a nuisance nobody wants. Later, `tools/import/ohm.mjs` writes OpenHistoricalMap outlines into `data/geo/presences/`; ODbL and CC BY-SA 4.0 are not compatible in either direction (OSMF's position; unverified for the specific 4.0 text but treat as true). A root licence claiming BY-SA over that directory is a licence violation the day the import lands, and it is irreversible once third-party contributions exist, exactly as `CONTEXT.md` warns.

**Severity.** blocks M0 (`LICENSE` is an M0 deliverable).

**Fix.** `LICENSE` = MIT (or similar) for code; `data/LICENSE` = CC BY-SA 4.0 for records; `data/geo/LICENSE` per source (public domain for Natural Earth, ODbL for OHM later, CC0 for Wikidata). The envelope `license` field already exists; make it an enum `{CC-BY-SA-4.0, ODbL-1.0, CC0-1.0, PD}` and have the validator enforce the allowed value per directory. Keep imported geometry as a separate collective database (own directory, own attribution in the UI), never merged into record files. State in `about.html` that relicensing is not possible; that is the honest consequence.

## 11. The time model has four gaps that are cheap now and expensive under contributors' data

**Problem.** No open-ended intervals, a `date` string with an unresolved calendar and year-0 conflict, an arrow-of-time rule that rejects legitimate fuzzy edges, and no cycle check.

**When it bites.** (a) `Kingdom of Spain` as a presence, or "Portuguese Macau" before 1999, needs `end: null`; the schema has no ongoing state, so contributors put `9999`. (b) `"date": "1415-08-21"` is Julian (Gregorian arrives 1582); a contributor enters a 1600 date in Gregorian; nothing records which. ISO 8601 expanded years use astronomical numbering with a year 0, so `"-0044-03-15"` is 45 BCE under the scheme you have chosen; the two conventions will be mixed in one field. (c) "Arrow of time using the honest bound": for `-9600..-9000 → -9400..-8800` the honest bound (`from.start.max ≤ to.start.min`) rejects; nearly every prehistoric edge is between overlapping fuzzy intervals. (d) `≤` on integer years permits `A→B` and `B→A` both in 1415; `graph.js` then loops or, with a visited set, silently returns different consequences depending on where you start.

**Severity.** blocks M0.

**Fix.** `end: null` means ongoing, in `interval.json`. `date` is display-only, recorded as the source gives it, with a `calendar: julian | gregorian` default by year; only integer years drive logic, through one `toAstronomical()` in `dates.js` that every arithmetic call uses (the timeline scale included). Arrow of time on fuzzy intervals: fail on the lenient bound (`from.start.min ≤ to.start.max`), warn on the honest one. Add a DAG check as an invariant; where two same-year events have `date`, use it to break the tie. Also decide now that `where` is optional for long processes (the Atlantic slave trade has no honest point), which makes them timeline-only records rather than a dot in the ocean.

## 12. Dispute and source shapes are underspecified in the one place that is hard to change later

**Problem.** `dispute` is a string but "must cite sources", `sources` cannot distinguish supporting from dissenting citations, and a source record needs no resolvable identifier.

**When it bites.** A contributor writes a dispute, puts the dissenting book into the envelope `sources`, and the panel renders it as support for the link. The reviewer checking "sources actually support the claim" cannot tell which is which. Separately, `russell-2000-henry` with a made-up title passes every invariant; "every node needs a source" is satisfied by inventing a source, and the only defence is the reviewer looking it up by hand for every record.

**Severity.** blocks M0 (it is the form's field shape); the fake-source problem is fix-before-contributions.

**Fix.** `dispute: { text, sources: [ { source, locator } ] }`. Source records require at least one of `isbn`, `doi`, `url`, or for `primary` a `repository` + `reference`; `web` sources require `accessed` and are encouraged to be an archive URL. The Action can resolve DOI/ISBN against a public API and comment the title it found next to the one submitted; that is not a runtime dependency. Widen `type` now: `book, chapter, article, thesis, primary, dataset, web`; `dataset` is what a Wikidata or Natural Earth import cites, otherwise the "every node has a source" rule has no honest answer for imported actors.

## 13. `probable` is where everything will go

**Problem.** The three-value scale mixes two axes (strength of the claim; existence of disagreement), so `probable` becomes the default that avoids writing a dispute and `consensus` costs nothing to assert.

**When it bites.** After 500 edges from twenty contributors, 80% are `probable`, `consensus` is what the contributor felt strongly about, and the interface's promise ("shows the difference") is showing a mood.

**Severity.** fix before contributions open.

**Fix.** Define them by evidence, checkably: `consensus` requires at least two sources by different authors (validator can check author overlap between source records); `probable` = supported by cited sources, no known dissent; `disputed` = as designed. State the definitions in `about.html` and the PR template. Do not add a fourth value.

## 14. The zero-dependency JSON Schema validator can lie about what it checks

**Problem.** A home-rolled subset validator silently ignores any keyword it does not implement, so the schema documents checks that are not performed.

**When it bites.** Someone adds `"format": "date"` or `"uniqueItems": true` to `event.json` in a PR; CI is green; a year later half the `date` fields are free text.

**Severity.** fix before contributions open.

**Fix.** Implement the subset (`type, enum, const, required, properties, additionalProperties, items, pattern, minimum, maximum, minLength, maxLength, oneOf, $ref` to relative repo paths) and make it fail closed: unknown keyword in a schema file is a validation error of the schema itself, tested in `tests/`. Keep it to draft 2020-12 spelling so the files remain readable by external tools. Note that `core.js` in the browser must load the index to validate references (`from`, `to`, `sources[].source`), otherwise the form's "live validation" is schema-only and the first thing the Action rejects is what the form said was fine.

## 15. Index determinism, on this machine

**Problem.** The freshness check is a byte comparison, and the repo lives on a Windows mount under OneDrive.

**When it bites.** `localeCompare` for sorting depends on ICU and differs between Node builds; key order follows insertion unless sorted recursively; a file saved with CRLF on the Windows side makes the local index differ from CI's; OneDrive syncing `.git/` produces the well-known corrupted-object and lock-file failures; the filesystem is case-insensitive so two ids differing by case collide silently; edge file names of 100+ characters under a path that is already 80 characters approach the 260-character Windows limit for tooling that does not opt into long paths.

**Severity.** watch (the CRLF and sort items are M0-cheap).

**Fix.** `build-index.mjs`: recursive key sort, code-unit comparator, trailing newline, `.nvmrc`/`engines` pinned to the CI Node major. `.gitattributes`: `* text=auto eol=lf`. Slug regex already forces lowercase; keep it. Move the working copy out of OneDrive (a WSL-native path); this is the single most likely cause of a confusing week.

## 16. The sketch opens contributions before the model is tested, against `CONTEXT.md`, without saying so

**Problem.** `CONTEXT.md` says contributions stay closed until the schema is stable and names 1580–1640 as the test; M2/M3 open the pipeline after ~20 records, and the sketch does not list this as an amendment.

**When it bites.** The first schema change you want (and findings 4, 5, 9, 11, 12 above are all evidence you will want several) lands after strangers' files exist.

**Severity.** watch, but decide now.

**Fix.** Gate M3 on the 1580–1640 chain existing and coherent, and on a record count where you have personally hit the model's edges (a few hundred, not 20). M2 can still ship, tested by you, with the issue templates unpublished. Two other silent drops to call out explicitly in `ARCHITECTURE.md`: `CONTEXT.md`'s "strength" on edges is gone (decide that convergence orders by type then confidence, and say so, or bring strength back now); commit messages in Portuguese per `CLAUDE.md` versus everything-in-English.

## 17. Translation overlays go stale silently

**Problem.** An overlay has no link to the version of the base text it translated.

**When it bites.** The English `explanation` is rewritten after review; `data/i18n/pt/<id>.json` keeps translating the old argument; the Portuguese reader sees a claim the English record no longer makes.

**Severity.** watch; the field is one line to reserve now.

**Fix.** Overlay carries `baseRevised`; validator warns when it differs from the base record's `revised`; the panel falls back to English for stale fields. Drop `lang` from the envelope, or validate it as `"en"`; as designed it invites Portuguese base records.

## 18. Reserved things to drop from M0, and one that should not exist

**Problem.** Empty folders and named future scripts are speculation that costs attention, and `data/generated/` contradicts the project's one non-negotiable rule.

**When it bites.** A repository whose rule is "no AI-generated historical claims, ever" ships with a folder named for them and validator carve-outs for it; a contributor reads that as the plan. `tags: []` with no vocabulary is a junk drawer within a year. `parent` on regions is dead if finding 4 is accepted. `shards/`, `land-<epoch>`, `tools/import/{paleo-coast,ohm,wikidata-actors}.mjs` are names, not decisions.

**Severity.** blocks M0 only in the sense that it is cheaper to not create them.

**Fix.** Create no `.gitkeep` folders. Reserve by one line in `ARCHITECTURE.md` each. Remove `data/generated/` from the plan entirely; if that layer ever comes, it gets its own design against the rules already in `CONTEXT.md`. Remove `tags` until there is a closed vocabulary with a reason. Keep `actors: []` only if the validator accepts it empty and rejects it non-empty until `actors/` exists.

## 19. Scale numbers, for the record

**Problem.** Nothing here blocks anything, but the sketch has no figures.

**When it bites.** GitHub Pages: published site soft-capped at 1 GB, 100 GB/month bandwidth, 10 deploys/hour (unverified, my recollection of the documented limits). 15,000 record files at ~1–2 KB is ~25 MB; fine. Deploying tens of thousands of small files as a Pages artifact is slow (minutes) but works. A full-text index at 5,000 events is 5–15 MB uncompressed, which is why finding 3 splits topology from text. SVG holds 5,000 marks comfortably; at 50,000 with pan/zoom it stutters, and the fix is rendering only the visible year window (not loading only it) and at most one `<g>` per lane, not a map library. Browser caching: the index changes on every merge; put a content hash in the manifest and name index files by it so they can be `immutable`, with only `manifest.json` uncached.

**Severity.** watch.

**Fix.** Write the numbers into `ARCHITECTURE.md` so the next person does not re-derive them, and add the hashed file names to `build-index.mjs` now, since renaming index files later is a `data.js` change.
