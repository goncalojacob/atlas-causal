Atlas causal

What this is, how to read it, and under what licence.

What this is

A map and a timeline over the same thing: a graph. Events are nodes. The links between them are edges, each one carrying a type, a confidence level and a written argument for why the link is there. You pick an event, follow its consequences forward, and — this is the part the format exists for — see which other branches fed the endpoint you arrived at, so that the path you happened to walk does not look like the explanation.

The first slice is Portuguese expansion, 1415 to 1580, chosen because its consequences cross continents, which is what the format is for. If the model survives that period it generalises; if it does not, better to find out on a small map.

The hard part was never the map. No dataset states that one thing caused another across four centuries and two oceans: that has to be written, by a person, with sources. So this is editorial work with a map attached rather than a data visualisation, and every claim in it is signed and cited. Nothing here is generated by a language model — not the summaries, not the arguments, not the disputes. A model will produce a fluent causal story about any pair of events, including unrelated ones, and in a history site that is not a small flaw but total failure.

How to read it

The five edge types

An edge is one of caused, enabled, reacted-to, precondition-of or inspired. There is no generic type and there never will be: collapsing these into plain causation is how a map of history turns into cheap determinism. The type is doing real work, and choosing the right one of the five is part of what a reviewer checks.

The three confidence levels

Confidence is defined by evidence, so that it can be checked rather than felt.

consensus
The link is accepted. It requires at least two cited sources by different authors — a necessary condition, not a sufficient one: a reviewer still judges whether they really agree.
probable
Supported by the sources cited, with no known dissent. Most edges live here, and that is honest: it says the argument rests on the sources given and nobody has been found arguing the other way.
disputed
Qualified historians disagree about the link itself — whether it exists, what type it is, or how much it carries.

A disputed edge

A disputed edge stays in the atlas. Removing it would be picking a side, and being able to see the disagreement is more interesting than a clean answer. It is drawn as a dashed line on the map, marked in the panel, and it is never walked through silently: following a chain across one tells you that you have, and shows you who disagrees and what they cite. The dissenting citations are kept apart from the supporting ones, so a book that argues against a link is never displayed as evidence for it.

Records are never deleted. A record that turns out to be wrong or duplicated becomes a tombstone that still resolves the old link, pointing at whatever supersedes it: a URL someone shared keeps working.

What the map does not draw

Coastlines, and no borders. A crisp border is a modern idea, and drawing sharp lines for most of history projects the nation-state backwards onto periods that had no such thing. When territories are added they will have to be representable as diffuse zones, not as outlines. The timeline's lanes are continents, derived from the coordinates of each event rather than stored on it, so that redrawing the lanes never means rewriting the records.

Licences

Three, because one licence cannot honestly cover code, prose and imported geometry.

  • The code — everything under src/, tools/ and tests/ — is MIT. CC BY-SA on JavaScript is a nuisance nobody wants.
  • The records — everything under data/: every event, edge and source, which is to say all the writing — are CC BY-SA 4.0. Use them, including commercially, with attribution, and share what you build on them under the same terms.
  • The geometry under data/geo/ keeps the licence of its source. The present-day coastlines and the lane polygons derive from Natural Earth, which is public domain; its makers ask to be credited and are, here and in data/geo/LICENSE.

Why this cannot be changed later

Relicensing needs the permission of everyone who holds copyright in the thing being relicensed. The moment a stranger's paragraph is merged, that set includes them, and it grows with every contribution. There is no realistic point after which all of those people can be found and asked. So the licence is not a default that can be revisited when it becomes inconvenient: it is a decision taken once, before contributions opened, and it is final. The same reasoning is why imported geometry under an incompatible licence — ODbL, for instance — will live in its own directory with its own attribution, never merged into a record file.

Contributions

Not yet open. The schema is still being tested against the first period, and migrating a hundred contributors' records is far harder than migrating your own — so the pipeline is built and tested before it is announced, not after.

When it opens, it will work like this. A form builds a bundle: an event, the edges that connect it and any source not already in the bibliography, validated in your browser against the records already here, so that references resolve and the arrow of time holds before you send anything. The form copies the bundle to your clipboard and opens one issue. A maintainer reads that issue; only when they accept it does it become a pull request, and a person still reviews the argument, the sources and the confidence before it is merged. No sources, no merge. The repository is the database, GitHub is the plumbing, and the judgement stays human — that is not a limitation to engineer away, it is the design.

The reasoning behind all of this is in CONTEXT.md in the repository; the structure is in ARCHITECTURE.md; what is built so far is in STATUS.md.
